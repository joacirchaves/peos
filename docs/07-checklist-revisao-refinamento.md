# Checklist de Revisão de Refinamento — PEOS

Use este checklist antes de mover uma história para desenvolvimento.

## 1. Problema e objetivo

- [ ] O problema está descrito de forma clara.
- [ ] O usuário ou área impactada está identificado.
- [ ] O objetivo da história está explícito.
- [ ] O resultado esperado é compreensível.

## 2. Escopo

- [ ] O escopo incluído está claro.
- [ ] O fora de escopo está registrado.
- [ ] Não há mistura indevida entre várias entregas grandes.
- [ ] A história pode ser desenvolvida e validada de forma objetiva.

## 3. Regras de negócio

- [ ] As regras estão escritas em linguagem simples.
- [ ] Não há regras contraditórias.
- [ ] As exceções conhecidas foram registradas.
- [ ] As regras são suficientes para orientar desenvolvimento e QA.

## 4. Critérios de aceite

- [ ] Os critérios estão em português BR.
- [ ] Os critérios usam Dado / Quando / Então quando aplicável.
- [ ] Cada critério é testável.
- [ ] O fluxo principal está coberto.
- [ ] Fluxos alternativos relevantes estão cobertos.
- [ ] Cenários de erro relevantes estão cobertos.

## 5. Dependências

- [ ] Dependências técnicas foram mapeadas.
- [ ] Dependências de negócio foram mapeadas.
- [ ] Integrações necessárias estão explícitas.
- [ ] Dados necessários estão identificados.
- [ ] Decisões pendentes foram registradas.

## 6. Subtarefas

- [ ] As subtarefas representam trabalho executável.
- [ ] Backend, frontend, dados, QA e documentação foram considerados quando aplicável.
- [ ] Não há subtarefas genéricas demais.

## 7. Estimativa

- [ ] A história foi estimada em Fibonacci.
- [ ] A estimativa considera complexidade, incerteza e dependências.
- [ ] Histórias acima de 13 pontos foram avaliadas para quebra.

## 8. Decisão final

- [ ] Pronta para desenvolvimento.
- [ ] Precisa de ajustes.
- [ ] Deve voltar para discovery.
